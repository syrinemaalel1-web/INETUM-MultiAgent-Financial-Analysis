Les PDFs de la CMF sont des PDFs natifs (texte sélectionnable, pas des scans).
→ NE PAS activer l'OCR (EasyOCR, Tesseract, etc.)
→ NE PAS utiliser les pipelines OCR de Docling
→ Utiliser uniquement le pipeline texte natif de Docling :
   PipelineOptions avec do_ocr=False et do_table_structure=True (TableFormer)

# RÈGLES DE CONSTRUCTION DU MARKDOWN

## Frontmatter YAML (obligatoire en tête)
- Bloc délimité par ---
- Champs : société, année, type_état, source_file,
  date_extraction (ISO8601), nb_pages, nb_tableaux,
  nb_sections, statut (succès|partiel|échec)
- Extraire société/année/type_état depuis le nom du fichier

## Sections (headings)
- H1 : titre du document ({société} — {type_état} {année})
- H2 : chaque section détectée (BILAN, RÉSULTAT, FLUX, etc.)
- H3 : chaque tableau dans sa section parente

## Tables Markdown
- Chaque tableau Docling converti en table Markdown standard
- Titre du tableau en H3 : "### Tableau {type_tableau} — Page {n}"
- Sous le tableau : ligne vide pour séparabilité
- Si le tableau est vide ou non parseable → écrire :
  > ⚠️ Tableau non extractible (page {n})

## Texte complet
- Après toutes les sections, ajouter une section H2 :
  ## Texte Brut Complet
  avec le texte intégral du document (utile pour recherche full-text)

## Footer
- Dernière ligne : note d'extraction (moteur, date, pipeline)

# STACK TECHNIQUE
- Extraction PDF   : docling (DocumentConverter + TableFormer uniquement)
- Validation       : pydantic v2 (valider le frontmatter avant écriture)
- Logging          : module logging standard (extract.log + console)
- Progression      : extract_progress.json (reprise sur interruption)
- CLI              : argparse
- Chemins          : pathlib (compatible Windows/Linux)

# ARCHITECTURE — Classe DocumentExtractor

## __init__
Configurer DocumentConverter SANS OCR :
  from docling.datamodel.pipeline_options import PdfPipelineOptions
  pipeline_options = PdfPipelineOptions()
  pipeline_options.do_ocr = False              ← OBLIGATOIRE
  pipeline_options.do_table_structure = True   ← TableFormer activé
Configurer logging. Créer dossiers si inexistants.

## extract_single(pdf_path: Path, output_dir: Path) -> dict
- Convertit le PDF via Docling en DoclingDocument
- Appelle _extract_sections(), _extract_tables(), _detect_section_types()
- Construit le Markdown final via _build_markdown()
- Valide le frontmatter via Pydantic avant écriture
- Sauvegarde : output_dir/{stem}.md
- Retourne : {"status": str, "path": str, "message": str, "nb_tables": int}
- Gère : PDF corrompu, PDF protégé, timeout > 120s

## extract_batch(input_dir: Path, output_dir: Path,
                 force_retry: bool = False) -> None
- Scanne input_dir pour tous les .pdf
- Si force_retry=False : skip si {stem}.md existe déjà dans output_dir
- Boucle sur extract_single avec barre tqdm
- Met à jour extract_progress.json après chaque fichier
- Affiche rapport final : total OK / skip / erreur

## Méthodes privées (chacune < 30 lignes)
- _extract_sections(doc) -> list[dict]
    → retourne [{"titre", "niveau", "contenu", "page", "type_section"}]
- _extract_tables(doc) -> list[dict]
    → retourne [{"titre", "page", "type_tableau", "markdown_table": str}]
    → Utiliser doc.tables et convertir chaque table en Markdown via pandas
- _detect_section_type(titre: str) -> str
    → Retourne : BILAN_ACTIF | BILAN_PASSIF | ETAT_RESULTAT |
                 FLUX_TRESORERIE | VARIATION_CAPITAUX | NOTES_ANNEXES | AUTRE
- _build_markdown(metadata: dict, sections: list,
                  tables: list, full_text: str) -> str
    → Assemble le fichier Markdown complet (frontmatter + corps)
- _parse_filename_metadata(pdf_path: Path) -> dict
    → Extrait société/année/type depuis "{SOCIÉTÉ}_{ANNÉE}_{TYPE}.pdf"

# DÉTECTION DES TYPES DE SECTIONS (états financiers tunisiens)
_detect_section_type() via regex case-insensitive :
- "BILAN" + ("ACTIF" | pas "PASSIF") → "BILAN_ACTIF"
- "BILAN" + "PASSIF"                 → "BILAN_PASSIF"
- "RÉSULTAT" | "COMPTE DE RÉSULTAT"  → "ETAT_RESULTAT"
- "FLUX" | "TRÉSORERIE"              → "FLUX_TRESORERIE"
- "CAPITAUX PROPRES" | "VARIATION"   → "VARIATION_CAPITAUX"
- "NOTE" | "ANNEXE"                  → "NOTES_ANNEXES"
- Aucun match                        → "AUTRE"
Tagger chaque tableau avec son type_tableau détecté depuis le titre
ou depuis la section parente si titre ambigu.
